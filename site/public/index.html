The work behind the claim, sealed so anyone can check it.

An agent reports a result. κ evidence is everything that stands behind it: each proposal, test and verdict, the failures too, named by the hash of its own bytes and tied into one root. It is the record that Proof of Agentic Work is made of.

Why we use it

Proof of Agentic Work needs a record that cannot be tidied afterwards.

When agents do research, what travels is the headline: a score, a bound, a sentence saying it worked. The attempts that failed, the tests that were run and the order things happened in stay behind with whoever ran the agents. Proof of Agentic Work (PoAW) is our discipline for publishing the work itself, in a form a stranger can re-derive. It asks five things of its record. Each one is a property of this format.

  • 1
    PoAW asks

    A stranger can check it, with no one's permission.

    κ evidence gives

    Everything is named by the hash of its bytes. Verifying needs the bundle and SHA-256: no service, no account, nobody to ask.

  • 2
    PoAW asks

    Claims are recomputed, not believed.

    κ evidence gives

    A stated fact names a published rule. The verifier runs the rule over the sealed rows and requires the same answer, byte for byte.

  • 3
    PoAW asks

    Failures stay on the record.

    κ evidence gives

    A refuted attempt is a leaf like any other. The root commits to it, and the next root commits to that root, so it cannot be dropped later without breaking every root after it.

  • 4
    PoAW asks

    A proposer does not choose its own tests.

    κ evidence gives

    A proposal is sealed first. The tests it faces are drawn from its κ, and the draw is itself a record in the bundle that the verifier checks against the proposal.

  • 5
    PoAW asks

    The root comes before the claim.

    κ evidence gives

    A bundle is minted and verified before the result is submitted, and the submission quotes the root. The number may be copied anywhere. The root says where it came from.

The PoAW paper is forthcoming. Everything on this page is the evidence layer it runs on, which is open and running today.

      How it works

      A κ is the name a thing gives itself.

      Type anything. Its κ is computed here from the bytes alone. Nobody assigns it, and nobody can assign the same one to different bytes.

      • 1

        Everything is named by its bytes

        A file is stored under sha256: of its content. A structured object is first written in deterministic CBOR, which gives it exactly one byte form, and is then named the same way.

      • 2

        Every row points at its source

        A row of evidence carries a typed link to the sealed file it was read from. A row with no source in the bundle does not verify.

      • 3

        Every fact is recomputed

        A fact that the verifier cannot recompute from sealed bytes under a published rule is not accepted. An unknown rule fails.

      • 4

        One root seals the run, and roots chain

        The root commits to every name in the bundle through a Merkle tree, and may name the root before it. Quoting one root is quoting the whole history behind it.

      Stated plainly

      What a root proves, and what it does not.

      It tells you

      • The record is complete and unaltered since it was sealed.
      • Every row traces to sealed source bytes.
      • Every stated fact follows from those rows under a published rule.
      • With a signed root, which key stands behind it.

      It does not tell you

      • That the source bytes were honestly produced. A sealed log is exactly the log that was sealed.
      • That an unsigned bundle has an author.
      • That anything is registered with a registry.

      Rules can close the first gap where the work allows it. A rule may re-run a proof verifier on the sealed proof, so its fact is recomputed truth and not a recorded verdict.

      Use it

      Python 3. No packages.

      The core, the minter and the verifier run on the standard library alone, so everything a verification depends on can be read in an afternoon.

      # get it
git clone https://github.com/mitchuski/kappa-evidence-mage
cd kappa-evidence-mage

# mint the example bundle, then re-derive it from its root
python example_mint.py
python verify_bundle.py out/example

# or from your own code
python -c "import kappa as K; print(K.kappa_from_value({0: 'example/thing/1', 1: 'hello'}))"

      To seal your own work, write one thin adapter: put each source file as a blob, each row as a record, state the facts as checks, and call the root. The example is the whole pattern in thirty lines.
